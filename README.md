## 3. 학습

### 3-1. BC (시범 수집 → 학습 5개 → 선택 → 최종 평가)

```powershell
# 1) 시범 데이터 수집 (600판, SUMO 7개로 약 3시간). 결과: data\demo_v2.npz
python collect_demo.py --episodes 600 --workers 7 --name demo_v2

# 2) BC 전체 과정 (약 10시간): 학습 seed 0·10·20·30·40 → 가벼운 평가(seed 99 × 50)
#    → 상위 3개 중간 평가(seed 100 × 100) → 1위 최종 평가(seed 110~150 × 300)
python run_all_BC.py --data data\demo_v2.npz

# (하나만 학습할 때)
python train_bc.py --data data\demo_v2.npz --epochs 100 --seed 30 --out-dir results\bc_v2_s30
```

- 시범 운전자는 SUMO 다 (신호·앞차·양보를 SUMO 가 지킨다). 도착한 시범만 저장한다.
- 지난번 최종 BC 설정: 100 epoch, batch 256, lr 3e-4, 검증 20% (에피소드 단위).

### 3-2. PPO 단독 (단계별 보상 일정)

```powershell
# 1) 5분 동작 확인 (꼭 먼저)
python train_ppo_curriculum.py --run smoke --workers 2 --total 16384 --n-steps 512 --eval-every 8192 --eval-episodes 1

# 2) 본 학습 (SUMO 6개 예시. 10만 스텝마다 seed 99 × 20판 평가, 가장 좋은 모델은 best.pt)
python train_ppo_curriculum.py --run ppo_v2 --workers 6

# 3) 끊겼을 때 이어서
python train_ppo_curriculum.py --run ppo_v2 --workers 6 --resume
```

- 단계: 1 달리기 → 2 충돌·이탈 벌점 올리기 → 3 규칙 벌점 올리기 → 4 굳히기. 자세한 내용은 파일 맨 위 설명.
- 이 파일은 지난번 마지막 설정(**v8**)이다. 지난번 모델(280만 스텝)은 v3 → v8 로 중간에 설정을 바꿔 가며 이어서 학습했고,
  이번에는 처음부터 v8 설정으로 시작한다.
- 속도 참고: SUMO 6개로 초당 약 30스텝 → 280만 스텝에 약 26시간.
- 결과: `results\ppo_v2\` (`train_log.csv`, `eval_log.csv`, `events.log`, `best.pt`, `ckpt_<스텝>.pt`). `best.pt` 는 `eval_daehakro.py` 로 그대로 평가할 수 있다.

### 3-3. BC+PPO, 약한 BC+PPO (②·③)

- 각자 코드는 **새 파일로** 추가한다 (1절). 환경은 `from env.daehakro_env import DaehakroEnv` 로 불러 쓰고, 환경 설정은 바꾸지 않는다.
- 시작점 BC 모델은 3-1 의 방법으로 **v3 환경에서 다시 만든 BC 모델**을 쓴다 (② 기준).
  v2 BC 모델(관측 48개)은 v3 환경(관측 51개)에서 불러올 수 없어 이 저장소에 넣지 않았다. v3 BC 모델이 나오면 여기에 경로를 적는다.
- 학습 보상을 바꾸려면 환경을 만들 때 `reward` 인자로 `{이름: 값}` 을 넘긴다 — `REWARD` 표에서 같은 이름의 값만 덮어쓴다
  (예: `{"off_route_penalty": 20.0}`). 학습 도중에 바꾸려면 `env.drw[이름] = 값` (`train_ppo_curriculum.py` 의 방식).
  표에 없는 감점은 학습 코드 안에서 따로 계산해 더한다. 어느 경우든 `env/` 파일은 고치지 않는다.

### 3-4. 다른 형식의 모델을 평가하려면 (`--loader`)

`test.py` 는 수업 형식의 BC·PPO 만 불러온다. 내 모델이 다른 형식이면 `example_loader.py` 를 복사해서 고친다.

```powershell
copy example_loader.py my_loader.py      # load_agent(model_path, obs_dim, act_dim) 를 내 형식에 맞게
python eval_daehakro.py results\my_run\model.pt --loader my_loader.py --episodes 300 --seed 110
```

`load_agent` 가 돌려주는 객체에 `predict(obs, deterministic=True)` 가 있고, `[가감속(-1~1), 차로변경(+1 왼쪽 / 0 유지 / -1 오른쪽)]` 을 돌려주면 된다.

### 3-5. 수업 제출용 데이터 수집 (`collect_pomdp_data_daehakro.py`)

수업의 `collect_pomdp_data.py` 와 같은 형식(JSONL.gz + NPZ)에 대학로 항목 23개를 더해 모은다. 최종 모델이 정해진 뒤 쓴다.

```powershell
python collect_pomdp_data_daehakro.py --model results\ppo_v2\best.pt --episodes 100 --workers 6 --name final_v2
```

| 더한 항목 | 내용 |
|---|---|
| `state.sim_time` | 그 state 를 읽은 시뮬레이션 시각 (s) |
| `state.tls.<신호 id>` × 15 | 신호마다 연결별 값: 초록 1 / 노랑 0 / 빨강 -1. 순서는 `tls_index.json` 의 `order` (연결 합계 137칸) |
| `state.junction_foes` | `[상대 id, AV 가 상충 지점까지 m, 상대가 상충 지점까지 m, AV 가 양보해야 하면 1]` (이미 지나간 차는 뺌) |
| `state.persons` | AV 50 m 안 보행자 `[id, 어린이 1 / 어른 0, x, y, 속도, 있는 곳(횡단보도·보도 id)]` |
| `state.vehicles[].type_id`, `stopped`, `signals`, `assist` | 차종, 경로 정차 중(버스 정류장·학부모 차 정차만 true), 등 신호 비트, 긴급차 보조 상태 0~5 |
| `event.collision_with` | 충돌한 상대 id (없으면 null) |

- `vehicles[]` 에는 배경 차량만 있다 (AV 는 `ego_*` 항목). 긴급차 보조 상태: 0 없음 / 1 긴급차에 비켜 줌 / 2 꼬리물기 대기 /
  3 횡단보도·교차로 앞에서 줄이거나 세운 사이렌 긴급차 / 4 버스 끼워 주기 / 5 긴급차 통과 대기 (여러 개면 작은 번호).
- 수집을 시작할 때 데이터 폴더에 `tls_index.json`(신호 순서·연결)과 `daehakro.tll.xml`(신호 프로그램 사본)을 저장한다.
  신호 목록이나 연결 수가 기록 형식과 다르면 시작하지 않고 멈춘다.
- NPZ 에는 고정 길이 값만 더했다: `sim_time (N,)`, `tls (N, 137)`, `collided (N,)`. 길이가 변하는 항목은 JSONL 에만 있다.
- 속도 참고: 모든 차의 상태를 매 스텝 기록하므로 SUMO 하나당 초당 약 6스텝이다 (이 작업 공간 기준). `--workers` 로 나눠 돌린다.

## 4. 평가 규칙 (모든 역할 공통)

| 구분 | 조건 | 명령 |
|---|---|---|
| **공식 비교** | seed 110, 120, 130, 140, 150 × 각 300판 = **1,500판** | `python eval_daehakro.py <모델> --episodes 300 --seed 110` (seed 마다 따로, 터미널 5개 동시 가능) |
| 빠른 확인 | seed 99 × 20판 (PPO 학습 중 평가와 같음) | `python eval_daehakro.py <모델> --episodes 20 --seed 99` |

- 평가는 결정적 행동(`predict(obs, deterministic=True)`)으로 한다. 같은 seed 면 같은 교통이 나온다 (같은 코드·같은 SUMO 버전일 때만).
- 보고할 값: 도착, 충돌(차 / 보행자), 경로 이탈, 오래 멈춤, 시간초과, **위반 없이 도착**, 위반 건수(신호 / 횡단보도 / 양보 / 버스전용차로 / 실선 침범), 과속(스텝 수, 과속한 에피소드 수).
- 수업 기준: **충돌률 5% 미만**. 수업 평가는 충돌만이 아니라 비정상 정지·잘못된 경로·무한 대기 없는 '문제 없이 완주'도 본다.
- 공식 평가 1,500판은 오래 걸린다 (지난번 BC: SUMO 5개로 약 6.5시간).

## 5. 환경 요약 (참고 — 모두 수정 금지)

- **경로**: 이화장길 어린이 보호구역 → 대학로 → 혜화동로터리, 약 1.5 km. 1 스텝 = 0.5초.
- **관측 51개** (범위 -1~1, `env/daehakro_env.py` 맨 위 표), **행동 2개** [가감속 -1~1, 차로변경 +1/0/-1].
- **AV 는 정책으로만 움직인다**: SUMO 의 자동 판단을 끈다 (speed mode 0, lane change mode 0).
  환경이 명령을 실행하지 않거나 줄이는 경우는 수업 코드에 있는 것뿐이다 — 차선 변경은 옆 차로 앞뒤 간격 검사를 통과할 때만 실행하고
  (걸리면 그 스텝은 차로 유지), 교차로 안에서는 차선 변경을 실행하지 않고, 속도는 도로 전체 상한 50 km/h 를 넘지 못한다.
  없는 차로·보도로 가는 명령도 실행하지 않는다. 그 밖의 규칙(보호구역 30 km/h, 버스전용차로, 실선, 양보)은 감점으로 배운다 (v3).
  긴급차 보조는 일반 차량만 움직인다.
- **에피소드**: SUMO 를 켜면 300초 동안 차를 채운 뒤 AV 를 넣고, 같은 시뮬레이션에서 다음 AV 를 이어서 넣는다.
  시뮬레이션 시각이 2600초를 넘거나 '오래 멈춤'으로 끝나면 다음 에피소드는 SUMO 를 새로 켠다.
- **끝나는 경우**: 도착 / 충돌(범퍼 사이 2.5 m 안쪽, 충돌한 차는 제거) / 경로 이탈(경로로 이어지지 않는 차로의 끝을 1 m 넘게 지나치려 함) /
  오래 멈춤(240초 연속 정지) / 시간초과(2000 스텝 = 1000초).
- **위반** (에피소드는 계속된다):
  - 신호위반 — 정지선을 넘는 순간 실제 신호가 빨강 (v2)
  - 횡단보도 — 건너거나 건너려는 보행자가 있는 횡단보도에 들어섬 (행동을 정할 때 관측 기준)
  - 양보 — 양보해야 할 차 바로 앞으로 상충 지점에 들어섬 (행동을 정할 때 관측 기준)
  - 버스전용차로 — 버스전용차로(실선)에 들어섬. 들어갈 때마다 1건 (사이렌 차를 비켜 주려고 들어간 것은 제외) (v3)
  - 실선 침범 — 차로변경이 금지된 실선을 넘어 차로를 바꿈 (v3)
  - 과속 — 차로 제한속도를 1.8 km/h 넘게 넘은 스텝. 평가에 스텝 수와 과속한 에피소드 수로 나온다 (v3)
- **긴급차**: 90초마다 1대 출동 (구급차·소방차). **순간이동 없음** (v2).
- **보상표 기본값** (`env/daehakro_env.py` 의 `REWARD`):
  진행 +0.1/스텝(제한속도로 달릴 때) · 시간 -0.01/스텝 · 앞차에 바짝 붙음 최대 -0.05/스텝 · 사이렌 차 앞을 막음 -0.1/스텝 ·
  과속 최대 -0.3/스텝(넘은 비율만큼) · 버스전용차로 -0.3/스텝 ·
  도착 +10 · 차 충돌 -20 · 보행자 충돌 -40 · 신호위반 -15 · 횡단보도 -10 · 양보 -8 · 실선 침범 -3 · 오래 멈춤 -5 · 경로 이탈 -10.
  각자 학습 보상은 학습 코드에서 덮어쓴다 (예: `train_ppo_curriculum.py` 는 경로 이탈 -20, 차로 안내 감점 0.15 등).
